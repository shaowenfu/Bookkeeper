# M0 通知采样：使用说明

目标（见设计文档“里程碑 / 第一周要做的验证”）：用一个**只记日志**的通知监听器跑 7 天，收集 7 个目标 App 的真实支付 / 退款通知样本，并统计中行通知相对平台通知的延迟分布，用来定 M1 的去重窗口。

## 1. 拿到 APK

**方式 A：GitHub Actions（不用装 Android Studio）**

每次 push 都会自动构建。打开仓库的 **Actions → Build APK → 最新一次运行 → Artifacts**，下载 `bookkeeper-m0-debug-apk.zip`，解压得到 `app-debug.apk`。

> 默认每次构建用的是临时 debug 签名，**新 APK 不能覆盖安装旧 APK**（必须先卸载，数据会丢）。7 天采样期间如果要升级，先配置固定签名：
>
> ```bash
> keytool -genkeypair -v -keystore bk.jks -alias bk -keyalg RSA -keysize 2048 -validity 36500
> base64 -w0 bk.jks   # macOS: base64 -i bk.jks
> ```
>
> 在仓库 **Settings → Secrets and variables → Actions** 添加 `BK_KEYSTORE_BASE64`（上面的输出）、`BK_KEYSTORE_PASSWORD`、`BK_KEY_ALIAS`（`bk`）、`BK_KEY_PASSWORD`。`bk.jks` 自己保管好，不要提交到仓库。

**方式 B：本地构建**

需要 JDK 17+ 和 Android SDK（装 Android Studio 最省事，或设置 `ANDROID_HOME`）：

```bash
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

本机多次构建默认使用同一个 `~/.android/debug.keystore`，可以直接覆盖安装。

## 2. 安装与授权（一次性）

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

或者把 APK 发到手机上点开安装（需允许“安装未知应用”）。

打开 App，在 **概览** 页把四个状态点都变绿：

1. **通知使用权**：点“去授权”，在系统列表里打开“记账通知采样”。Android 13+ 侧载的 App 可能提示“受限设置”：先到 系统设置 → 应用 → 记账采样 M0 → 右上角菜单 → “允许受限设置”，再回来授权。
2. **允许发送通知**：用于常驻状态通知和断线告警。
3. **不受电池优化限制**。
4. 厂商 ROM（小米 / 华为 / OPPO / vivo 等）还要手动：允许**自启动**、后台运行设为“无限制”，并在最近任务里**锁定**本 App。

之后通知栏会有一条常驻的“记账通知采样 · 监听中 · 今日样本 N 条 · 自检 HH:mm”。

## 3. 采样期间（7 天）

- 正常使用各 App 付款。M0 验收：**7 个 App 的支付和退款通知各 ≥ 3 条**，可以主动做几笔小额支付和退款。
- 常驻通知显示“⚠”或收到“通知使用权已关闭 / 通知监听已断开”告警时，点开按提示恢复。
- **样本**页可以按 App 筛选、点开看全部 extras；**其他包名**页列出白名单外发过通知的包名（只记包名和次数），某个目标 App 没采到时在这里找它的真实包名并加入白名单；**监听日志**页记录每次断线 / 重连，断线时段内可能漏采。

### 存了什么

| 字段 | 说明 |
| --- | --- |
| `package_name`, `sbn_key`, `notification_id`, `tag` | 来源和通知身份 |
| `post_time` / `received_at` | 系统发出时间 / 本 App 收到时间（ms），加 `tz_id` |
| `title`, `text`, `big_text`, `sub_text`, `summary_text`, `text_lines`, `ticker_text` | 常用文本字段 |
| `extras_json` | **全部** extras 逐项转字符串，加上 actions 标题、channel、flags 等；图片只记尺寸 |
| `is_update`, `previous_id` | 同一个 key 内容变了（更新） |
| `repost_count`, `last_seen_at` | 同 key、仍在通知栏、文本和 extras 都相同的重发：不新增行，只计数（通知被移除后再出现算新样本） |
| `possible_duplicate_of` | 不同 key 但内容相同、10 分钟内出现：保留，但标记疑似重复 |
| `is_group_summary` | 分组摘要通知（通常是噪音，分析时默认排除） |
| `capture_source` | `posted`（实时）或 `snapshot`（重连时补抓的当前通知） |
| `removed_at`, `removed_reason` | 通知被划掉 / 点开的时间和原因 |

表结构刻意贴近设计文档的 `raw_event`（只追加、保留原文），M1 可以直接迁移。

## 4. 导出与延迟分析

在 **概览** 页点“导出 JSON”（推荐，含监听日志）或“导出 CSV”（Excel 可直接打开），文件保存在手机 `下载/Bookkeeper/`，也可以点“分享”发到电脑。

```bash
adb pull /sdcard/Download/Bookkeeper/ ./samples/
python3 tools/analyze_delay.py samples/bookkeeper-m0-XXXXXXXX-XXXXXX.json --pairs pairs.csv
```

脚本只用 Python 标准库，输出：

1. 各 App 样本数、带金额条数、含“退款”字样条数（对照 M0 验收）；
2. 中行通知与平台通知按**相同金额 + 时间最近**一一配对，延迟 = 中行 `post_time` − 平台 `post_time`：分位数（p50 / p90 / p95 / p99 / max）、直方图、按平台拆分；
3. **建议的 M1 去重窗口**（max(p99, max) × 1.5，取整到分钟，至少 2 分钟）；
4. 没配上的中行通知（将来的 `bank_only`）和没配上的平台付款通知（可能是零钱 / 余额 / 花呗，或金额没抽对）；
5. 监听断线时段。

参数：`--before 30`（平台最多比中行早多少分钟）、`--after 5`（平台最多比中行晚多少分钟）、`--include-summaries`、`--pairs out.csv`（导出配对明细，人工复核用）。

金额是用通用正则从文本里抽的（`¥12.34`、`12.34元`、`人民币12.34`、`支出…12.34` 等，跳过“余额”）。看过真实样本后，按需改脚本顶部的 `AMOUNT_PATTERNS`，这些规则也是 M1 解析器的起点。

## 默认白名单

| App | 包名 |
| --- | --- |
| 中国银行 | `com.chinamworld.main` |
| 微信 | `com.tencent.mm` |
| 支付宝 | `com.eg.android.AlipayGphone` |
| 抖音 | `com.ss.android.ugc.aweme` |
| 美团 | `com.sankuai.meituan` |
| 美团外卖 | `com.sankuai.meituan.takeoutnew` |
| 小红书 | `com.xingin.xhs` |
| 京东 | `com.jingdong.app.mall` |

装的是极速版 / 其他版本时（如抖音极速版 `com.ss.android.ugc.aweme.lite`、京东极速版 `com.jd.jdlite`），在“其他包名”页加进白名单即可。概览页会标出白名单里“未安装”的包名，方便发现写错的。
